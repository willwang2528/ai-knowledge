# 讨论记录

## 2026-07-25：为什么总是混淆召回、检索、粗排、精排和 Rerank？

### 用户问题

用户希望把容易混淆的概念放进一个主题讲透，重点用链路解释：

- 推荐系统中的召回、Matching、Candidate Generation、粗排、精排和重排是什么关系？
- RAG 中也有 Retrieval、Ranking、Rerank 等类似名词，它们与推荐系统是否相同？
- 每个阶段最重要解决什么问题？

用户已有的推荐链路理解：

```text
全量内容池
    ↓
召回 / Matching / Candidate Generation
    ↓
合并、去重、硬过滤
    ↓
粗排 / Pre-ranking
    ↓
精排 / Ranking
    ↓
重排 / Re-ranking / Post-ranking
    ↓
最终展示列表
```

### Agent 回答

用户给出的推荐链路基本正确。真正需要补充的是：这些术语不能只按中英文记忆，而要按三个问题理解：

1. 当前阶段面对多大的候选集？
2. 当前阶段主要优化覆盖、精度，还是列表整体约束？
3. 当前阶段允许为每个候选花多少计算成本？

统一框架：

```text
找候选
  ↓
判优先级
  ↓
整理最终列表
```

#### 推荐系统

```text
召回：找候选，重点是不漏且能在大规模运行
  ↓
过滤：保证候选合法、唯一、可展示
  ↓
粗排：低成本缩小候选，为精排减负
  ↓
精排：用丰富特征准确判断单个候选价值
  ↓
重排：优化列表整体体验与业务约束
```

#### RAG

```text
查询改写：让问题更适合搜索
  ↓
初次检索：从大规模 Chunk 中找高覆盖候选
  ↓
融合与过滤：合并多路结果并保证权限、去重
  ↓
Rerank：精确判断 Query—Chunk 相关性
  ↓
Context Packing：组织最终证据集合
  ↓
LLM 生成：把证据组织成答案
```

### 最关键的纠偏

#### 纠偏 1：召回不是“低质量排序”

召回的核心目标是建立候选集合。它必须快、覆盖广，并让后续模型真正有东西可选。

#### 纠偏 2：Recall 既可能是阶段，也可能是指标

- 召回阶段：系统组件。
- Recall@K：评价有没有漏掉相关对象的指标。

#### 纠偏 3：RAG 的 Rerank 不完全等于推荐系统的重排

- RAG Rerank：通常使用 Cross-Encoder 等模型，对初检候选做精确相关性判断。
- 推荐重排：通常在精排后处理列表级多样性、新鲜度、公平性和业务约束。

因此，按职责对应：

```text
RAG Retriever ≈ 推荐召回
RAG Reranker ≈ 推荐精排
RAG Context Packing ≈ 推荐重排的部分列表级职责
```

这里的 `≈` 表示工程职责相似，不表示算法和产品目标完全相同。

### 关键理解

1. 多阶段链路本质是计算预算漏斗。
2. 上游负责候选覆盖，下游负责更精确判断。
3. 后一层永远无法找回前一层已经漏掉的对象。
4. 粗排和精排不是算法名字，而是当前系统中的成本层级。
5. Rerank 的字面意思只是“再排一次”，必须结合系统位置理解。
6. 过滤、融合、排序是不同动作，不能混为一谈。
7. 最终应把每个术语绑定到输入、输出、规模、目标和延迟预算。

### 一句话复习

```text
推荐：召回保不漏，粗排保算得动，精排保判得准，重排保整页好。

RAG：改写让问题好搜，检索让证据入围，Rerank 让证据排准，Packing 让上下文够用。
```

## 2026-07-25：所以 Recall = Retrieval？

### 用户问题

所以 `recall = retrieval`？

### Agent 回答

**不严格相等。**

需要区分“中文工程阶段名”和“英文指标名”：

```text
中文推荐系统里的“召回阶段”
≈ Retrieval
≈ Candidate Generation

英文 Recall
= 召回率指标
= 相关对象中有多少被成功找回
```

在推荐系统语境里，中文工程师常把 Candidate Generation / Retrieval 这一层叫“召回”，所以说“召回层就是 Retrieval 层”通常成立。

但在严格英文技术表达里：

- `retrieval` 是从大规模集合中取得候选的过程。
- `recall` 是衡量漏没漏掉相关对象的指标。

例如：

```text
Retriever 从知识库取回 Top-100 Chunk。
知识库中共有 10 个相关 Chunk，其中 8 个进入 Top-100。
那么 Recall@100 = 8 / 10 = 0.8。
```

最不容易混淆的表达方式：

- 系统阶段写 `Retrieval / Candidate Generation（召回阶段）`。
- 评价指标写 `Recall@K（召回率）`。

### 关键理解

`Retrieval` 做动作，`Recall` 量结果；中文“召回”同时被用来翻译阶段和指标，才造成了混淆。
