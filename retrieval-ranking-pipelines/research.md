# 科研视角：多阶段检索与排序的技术演进

## 1. 最初的问题

推荐、搜索和 RAG 面对同一个基本矛盾：

> 如何在巨大对象集合上，以有限延迟和计算成本，找到少量高质量结果？

便宜模型可以扫描大规模数据，但判断不够细；昂贵模型判断更准，却无法对全量对象运行。因此形成级联架构：

```text
低成本、高覆盖候选生成
          ↓
小集合上的高精度排序
          ↓
面向最终任务的整体优化
```

## 2. 推荐系统演进

### 2.1 两阶段架构

2016 年 YouTube 推荐论文清晰描述了：

```text
Candidate Generation
        ↓
Ranking
```

Candidate Generation 从巨大视频库取得候选，Ranking 再用更丰富特征精确打分。这奠定了理解大规模工业推荐系统的基本坐标。

### 2.2 Pre-ranking 独立成层

随着候选规模和 Ranking 模型复杂度增加，两阶段之间出现新的计算缺口：

```text
Matching
  ↓
Pre-ranking
  ↓
Ranking
  ↓
Re-ranking
```

粗排研究的核心不只是“把精排模型做小”，而是：

- 在严格成本下保留精排真正看重的候选。
- 减少上游筛选造成的样本选择偏差。
- 协调召回、粗排和精排之间的目标。

### 2.3 从单项分数到列表目标

单个 Item 分数最高，不代表组合成列表后体验最好。后续研究把多样性、公平性、探索、新鲜度和长期价值加入列表级优化。

## 3. 搜索与 RAG 演进

### 3.1 从词法检索到 Dense Retrieval

BM25 等词法方法擅长精确关键词和实体匹配，但难以覆盖同义表达。

DPR 使用双编码器分别表示问题和段落，再通过向量近邻搜索候选：

```text
Query Encoder → Query Vector
Passage Encoder → Passage Vector
             ↓
       相似度与 Top-K
```

它把语义检索扩展到大规模语料，但独立编码限制了细粒度 Query—段落交互。

### 3.2 RAG 引入可检索外部知识

2020 年 RAG 工作把生成模型与可检索文档索引结合：

```text
问题
  ↓
Retriever 找证据
  ↓
Generator 基于证据生成
```

检索结果从“直接展示给用户”变成了生成模型的外部证据。

### 3.3 Retrieve & Re-Rank

双编码器适合全量初检，Cross-Encoder 适合小规模精确判断：

```text
BM25 / Bi-Encoder 检索 Top-K
              ↓
Cross-Encoder 重排 Top-K
```

这与推荐系统“召回 + 精排”的工程逻辑相似，只是搜索领域通常把第二阶段称为 Rerank。

### 3.4 Late Interaction 与 Agentic Retrieval

ColBERT 用 Late Interaction 在单向量检索和完整 Cross-Encoder 之间折中，说明 Retrieval 与 Rerank 的能力边界会随模型效率变化。

进一步的 Agentic Retrieval 则把一次固定检索扩展为查询拆分、数据源选择、重试和验证。

## 4. 代表论文

只保留理解主线所必需的论文。

### Deep Neural Networks for YouTube Recommendations

- **年份：** 2016
- **解决问题：** 深度推荐模型如何服务超大规模视频库。
- **核心思想：** Candidate Generation + Ranking 两阶段。
- **贡献：** 清楚展示大规模工业推荐的候选生成和精排分工。
- **局限：** 没有覆盖后来常见的独立粗排和复杂列表级重排。

### COLD: Towards the Next Generation of Pre-Ranking System

- **年份：** 2020
- **解决问题：** 粗排如何同时接近精排效果并满足线上成本约束。
- **核心思想：** 联合优化模型能力和实际计算成本。
- **贡献：** 将 Pre-ranking 明确为独立的算法—系统协同问题。
- **局限：** 结论来自特定工业广告系统，公开复现条件有限。

### Dense Passage Retrieval for Open-Domain Question Answering

- **年份：** 2020
- **解决问题：** 词法检索难以处理问题与答案之间的语义表达差异。
- **核心思想：** 双编码器 Dense Retrieval。
- **贡献：** 推动稠密语义检索成为开放域问答的重要范式。
- **局限：** 单向量独立编码的细粒度交互有限。

### Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

- **年份：** 2020
- **解决问题：** 纯参数模型知识难更新、难提供来源。
- **核心思想：** 结合参数化生成模型和非参数化文档索引。
- **贡献：** 奠定现代 RAG 的代表性范式。
- **局限：** 原始框架没有覆盖今天生产 RAG 的完整权限、混合检索、Rerank 和 Context Packing。

### ColBERT

- **年份：** 2020
- **解决问题：** Cross-Encoder 太慢，单向量双编码器交互不足。
- **核心思想：** 独立编码 Token 级表示，再执行 Late Interaction。
- **贡献：** 在检索效率和细粒度交互之间提供重要折中。
- **局限：** 多向量索引的存储和服务复杂度更高。

## 5. 关键科研结论

### 5.1 多阶段架构由计算约束自然产生

只要同时存在“全量对象巨大”和“高精度模型昂贵”，候选生成到精细排序的漏斗就会存在。

### 5.2 上游决定下游上限和数据分布

召回决定粗排和精排能看到什么。上游误杀不仅无法恢复，还会改变下游训练数据，形成样本选择偏差。

### 5.3 术语边界会随技术变化

更高效的交互模型可以把过去只能用于 Rerank 的能力前移到 Retrieval。因此术语不是永久固定的算法类别，而是当前系统在效果与成本之间划出的职责边界。

### 5.4 目标正在从“单项相关”走向“整体有效”

- 推荐系统关注列表体验、供给生态、公平性和长期价值。
- RAG 关注证据组合、可引用性、冲突处理和检索验证。

## 后续可以研究的点

以下内容留作后续独立研究，本次不细究：

- **跨阶段联合优化**：研究召回、粗排和精排如何共享训练信号。
- **样本选择偏差**：研究上游筛选如何影响下游学习。
- **Late Interaction 检索**：研究 ColBERT 类方法的质量、存储和延迟权衡。
- **LLM Ranker**：研究大模型进行 Pointwise、Pairwise 和 Listwise 排序的成本与效果。
- **列表级学习**：研究推荐多样性、公平性和长期价值。
- **Agentic Retrieval**：研究动态查询规划、多跳检索、重试与验证。
